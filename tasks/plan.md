# Qwen forecasts and six-hour episode scores for AirAware

Help residents near a Lima monitoring station compare the next six hourly PM2.5 concentrations and estimate the chance of at least one high reading during that window. Keep Qwen3.5-0.8B with rank-4 LoRA and alpha 8 as the experiment default. The existing direct head is the point-forecast control. Start with its frozen checkpoint if AirAware verifies its training and selection provenance against the window IDs and station-hours of the new blocks. Otherwise refit the same recipe on the admissible split.

## Handoff between repositories

| Producer | Consumer | Proposed contract |
| --- | --- | --- |
| AirAware | OpenTSLM | Versioned manifest with split, ordered window IDs, channels, units, transforms and hashes. Start with 24 hourly PM2.5 readings per window. AirAware retains the station, origin and observation times keyed by window ID. Training adds six measured targets and, for classification, one eligible binary label per window. |
| AirAware | Episode head | Supply a raw threshold in µg/m³ as a numeric vector `threshold_ug_m3[N]` in the versioned episode input archive, matched to window IDs. AirAware fixes it from unique training hours. OpenTSLM transforms it once, inside the same forecast path used at fit and inference. A research positive means at least one reading at or above that threshold at +1 through +6 h. AirAware owns missing-data eligibility, the percentile rule, onset matching and any changes to the definition. |
| OpenTSLM | AirAware | Preserve the legacy point export (`window_id`, `forecast_hour`, `predicted`, checkpoint hash). Add a versioned quantile export with levels 0.1, 0.5 and 0.9 and shape [windows, 6, 3] in original units. The classifier exports one finite raw logit per window for the entire six-hour interval. Each new export identifies its task, input manifest and model revision. |
| AirAware | ml-infra | Fit the probability calibration and interval reference on the calibration block, choose the warning rule in validation, then freeze them. Supply versioned artifacts for inference and scoring. ml-infra packages pinned code and runs it against those artifacts. AirAware produces the station-facing calibrated probability. |

## Implementation order

1. **Get a reference result before changing the trainer.** Use AirAware's fixture `docs/methodology/episodios-v1`. A history-only point archive has just window_id and history. Pass `--require-history-only` to the restored point exporter. The verified point export is the first milestone. A subsequent AirAware deliverable must implement and test horizon-specific residual intervals and a probability calibration curve for the maximum of the six point forecasts minus the station threshold. Archive ordered IDs, checkpoint hash and outputs so the new heads have a common comparator.
2. **Add the quantile candidate.** Reuse the decoder readout in `QwenForecaster`. Use one median per horizon and nonnegative learned distances to its endpoints to keep the three quantiles ordered by construction. Fit with pinball loss, invert the history scaling on the concentration axis, and use the median as the point prediction. Reject crossed/nonfinite exported values and report cross count and coverage on high readings. Report held-back MAE, coverage and interval width by horizon and station alongside the residual-interval reference. Keep the point model available if it wins.
3. **Add a separate episode candidate.** Use the same history, frozen threshold input, trainable projection/readout and rank-4 adapter recipe. Train one binary logit with binary cross-entropy for the whole window. Pass the threshold as an explicit scalar to the new task head alongside the decoder readout. Use (threshold − history mean) / history population standard deviation, substituting scale 1 on flat histories. For a future joint model use the frozen PM2.5 channel transform. Validate shapes, units, ID ordering and threshold-manifest hash on read. Apply the inverse concentration transform to quantiles only. Logits bypass that transform. Match eligible window IDs, seed, optimizer-step budget and input history across comparisons. Train with synthetic events until AirAware resolves real-label eligibility in #20/#43.
4. **Restore and release the chosen heads.** Version new checkpoint identities with task, target definition, rank/alpha, levels and input/transform hashes. The existing recovery path compares entire identity dictionaries. Preserve the original unversioned identity for legacy resume. Interpret legacy inference as the recorded point head and boolean LoRA flag (rank 4, alpha 8 if enabled). Test exact identity checks within each version, including rejection of a changed threshold artifact. Support old direct and persistence checkpoints and the current two-channel input views. Qualify new heads on one GPU first. A task mismatch must fail before an output is written.

The first handoff uses the existing direct path on five synthetic AirAware histories. Train subsequent candidates on a separate labeled fixture. Preserve the default legacy schema when the new task is absent. Restore the same checkpoint in a fresh process, repeat that export without targets, and compare the predictions in the original window order. AirAware scores the export against observations from a separate directory. Validate fit candidates with a fixed final step or an inner train-only split; leave the outer calibration, selection and held-out blocks to AirAware. AirAware owns data partitions, calibration, event-level metrics and finalist selection. Keep Lima-specific data and eligibility rules in that repository. The [implementation checklist](todo.md) identifies the tests for each change; the [existing inference guide](../environments/forecast/README.md) documents the entry points.
